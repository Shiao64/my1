# 每周主办确认信：设计稿（2026-11-21，待 Shiao 定）

方向文件第①件：「每周给有邮箱的主办寄确认信和小报告（一键 照常／取消／有改动）」。
这份只是设计，**还没写程序、没部署**。要改后端（Worker `tango-subscribe`、D1），Shiao 点头才动工。

## 1. 一句话

每周一上午给每位主办寄**一封**信，列出他这周的每一场。每场三个按钮：**✓ 照常**、**✗ 这周取消**、**✎ 有改动**。
主办按「照常」，网站卡片马上变成绿色「✓ 主办 X 天前确认」；按「取消」，卡片显示那天取消，收藏的人收到通知；
按「有改动」，打开回信，寄到 huodong@（原本就能自动更新）。信尾附一小段「上周网站上的反应」。

## 2. 寄给谁

- 范围和 huodong@ 寄信名单一样：**卡上有邮箱、活动在中国大陆／香港／台湾／澳门**的主办。按现在资料算，约 **27 个邮箱**，大多数只管 1 张卡，最多的管 3 张。
- **一个邮箱一封信**：同一位主办有好几张卡就合在一封里，不会一张卡寄一封。
- 韩国、日本、越南的卡先不寄（地区优先顺序）。
- 只用中文。

## 3. 什么时候寄、寄什么卡

- **每周一 10:23（北京）** 寄一次。每位主办一周最多收到一封（方向文件：每周最多打扰一次）。
- 信里放：
  - 每周固定的卡：这周那一场（日期、时间、场地、网站上现在显示的 DJ）；
  - 单次活动、大活动：**30 天内**要办的才放；
  - 这周没有场次的卡（例如每月一次、这个月已经办过）不放。整封信都没内容就不寄。
- **没回也不追**。连续 4 周一个按钮都没按，改成每月第一个周一寄一次；只要按过一次，就改回每周。
- 信末有「不要再寄这封信」，按了以后永远不寄（记在原本的退订表 `mail_unsub`）。

- 「有改动」= 打开回信，主题已经写好「有改动：Milonga V（GqufXmMX）11/27」，寄到 huodong@。走原本的来信流程，不用新做。

## 5. 按钮按下去以后

- 每个按钮是一条**带签名的链接**（写了卡号、日期、动作，14 天有效，别人伪造不了）。
- **点开先是一页「确认这周照常？[确认]」，要再按一次才算**。原因：QQ 邮箱、Gmail 会先自动「预先打开」信里的链接检查安全，如果点开就算，主办还没看就会被记成「照常」，甚至「取消」。
- 按了「照常」或「取消」，后台（D1 新表 `organizer_confirms`）记下：卡号、日期、动作、时间。同一场按两次，以后按的为准。「取消」以后再按「照常」，就是改回照常。
- 页面最后显示「已收到，网站几分钟内更新」，加一个「看网站上的卡片」链接。

## 6. 怎么写回网站（关键）

后台不能直接改网站资料（资料在 GitHub 仓库里）。做法沿用 huodong@ 的路子，但**不用 Claude 处理，程序直接改**：

1. 后台每 10 分钟（原本就有的定时任务）把新的确认整理成**一个**小文件 `data/inbox/<日期>-confirm-<编号>.json`，用原本的 GitHub 授权码开 PR（分支 `answer/confirm-…`）。
2. `inbox-guard` 照常放行，自动合并。
3. `inbox.yml` 在交给 Claude 之前，先跑新工具 `tools/apply_confirms.py`（像 `wechat_article.py` 那样的前置步骤）：
   - **照常** → 那张卡写 `confirmed: 当天`，也把 `updated` 改成当天（这算「确认活动还在办」）；
   - **取消** → 写 `cancelled_dates` 加上那一天，加一条 `temp_notices`（status cancelled，「主办确认这周取消」）；
   - 文件移到 `data/inbox/done/`。
4. 只改了这些字段，`inbox_autocheck.py` 加一条规则：判定能自动上线 → 合并 → R2 sync → 几分钟后网站更新。取消会自动发原本的活动变动通知。
5. 后台只信自己签名的确认，**而且只能改信里列出的那张卡**（和「组织者来信只能改自己的卡」同一个原则）。

为什么不让后台直接开「改 JSON」的 PR：活动 JSON 每个文件只有一行，两个 PR 同时改一定冲突。交到 `data/inbox/` 走原本的排队、按卡合并流程（`inbox-refresh.yml`），比较安全。
