# 探戈通 Tango Pass（TP）— 活动报名系统说明

**探戈通（英文 Tango Pass，简称 TP）** 是 ATM 自己做的活动报名系统：报名表 → 审核 → 收款 → 入场二维码 → 门口签到。名称 2026-11-22 Shiao 定；项目名称以后简称 **Tango Pass（TP）** 或 **探戈通**。报名者看到的画面不显示系统名称。

改这个系统前先读完本文件；改完要更新本文件（尤其「决定」与「现况」两节）。

## TP 职务、设置页和登入规则（2026-11-23；第一步、第二步都已在 11/23 上线）

以下是 Shiao 定的完整规则，取代以前的版本和旧的相关决定。

### 第一步：职务和权限（现在做）

#### 职务
- 管理员（张孝；11/23 前叫「平台管理员」）：管全部活动，代组织者任免总管。有全部权限，但平常不做取消、退款、收款，万一需要时才做（Shiao 11/23）。
- 总管：每场 1 位，组织者本人或其委托的人。BSTW：张孝当管理员，另由管理员任命一位总管（Shiao 11/23 同意；原本是张孝自己兼总管）。
- 经理（11/23 前叫「副总管」）：每场最多 3 位。日常工作，也负责现场收款。
- （现场经理：11/23 取消。）
- 前台：人数不限，只签到。

#### 任免
- 管理员任免所有人；总管任免经理、前台；经理只任免前台；前台不任免任何人。
- 任免＝新增、删除、升降级、重设密码、重发连结。不能任免同级和自己。
- 删除＝真删，马上失效、不能恢复；签到和收款纪录保留名字。
- 删除或降级经理时，提醒总管检查前台名单，需要时重设密码、重发连结。

#### 权限（只限自己那场活动；管理员不限）
| 操作 | 总管 | 经理 | 前台 |
|---|---|---|---|
| 扫码、签到 | ✓ | ✓ | ✓ |
| 撤销签到、扫码现场收款 | ✓ | ✓ | — |
| 审核、按截图记收款、批准到场付款 | ✓ | ✓ | — |
| 名单、邮箱、备注、全部账目 | ✓ | ✓ | — |
| 取消报名、退款 | ✓ | — | — |
| 护照姓名、导出 | ✓ | — | — |

换收款码归组织者；收款码按活动分开之前，只有管理员能换。

#### 操作
- 权限由后台检查，没权限的资料不传到手机。
- 一支手机一种身份，各人用自己的，不共用、不转发。
- 现场收款只能凭刚扫的码，收已批准到场付款的那一笔。
- 到场付款未付清不能签到。
- 退款累计不超过应退。
- 同一笔只有先处理的成功，后到的看到谁已处理。
- 审核、收款、退款、取消、撤销签到都显示名字和北京时间。

#### 设置页
- 分三栏：总管（1）、经理（最多 3）、前台。各栏显示人数，按任免规则显示按钮。
- 经理满 3 位时不能新增或升级，并说明原因。
- 前台只用签到页。
- 收款码只给组织者，目前是管理员。

### 第二步：登入（第一步上线后、正式发账号前）

- 管理员保留长密码。取代“一次性前台连结”和“网址就是工作证”。

### 第二步程序怎么落实（补充，不是规则原文；11/23 上线）

- 登入页 `/event/beijing-2027-tango-weekend/register/in/#<链接码>`：链接码 48 位，放在 `#` 后面；二维码就是这个链接，没有密码。打开就显示名字和职务（`/social/reg/login/hello`）。
- 每支登入的手机一行 `reg_device`（只存设备钥匙的指纹）。退出不删行，记 `ended_at` 和原因（replaced／reset／deleted／role／logout），那台手机才说得出为什么退出。
- 六位密码只存 HMAC（钥匙是 Cloudflare 密钥 `REG_PIN_PEPPER`，没设就不能登入）。太简单的规则在 `register.js` 的 `pinWeak`。
- 连错次数记在人身上：每次尝试先 +1 再比对，同时送 20 次最多也只算 5 次就锁（真 D1 测过）。锁 15 分钟后第 6～9 次照算，第 10 次停用，只有「重设」解开。
- 再输密码由后台按时间判断：总管、经理 12 小时；（旧的现场经理以北京时间 06:00 换天）；前台不再输，到 `EVENTS.<活动>.deskEnds`（BSTW＝2027-06-23 06:00 北京）失效。管理员不受这些限制。
- 任免、总管退款、总管导出：密码放在同一个请求（`pin`）。导出改成 `POST /social/admin/reg/export`；旧的 GET 导出只剩管理员能用。
- 台数：同一批写入里「新增这台、超过的最早几台退出」，几台同时登入也不会超过。
- 管理页、签到页网址带 `?k=<链接码>`：iPhone 桌面图标有自己的储存，从图标打开只要再输密码。单有链接码进不去。
- 旧的 40 位管理密码、`staff:` 前台钥匙、`?act=` 一次性前台连结：迁移 0024 清掉，后台也不再认；`/reg/door/activate` 回 410，签到页对旧连结说明原因。

### 已知失败（11/23 测出；Shiao 11/23 说「现在补」，已修好，11/23 上线）

- 两人同时确认最后一位会超卖 1 位 → 修法：剩余名额的检查写进确认（和已占名额时的修改）那一句 UPDATE 本身（`ROOM_SQL`）。真 D1：6 人同时抢最后一位 30 轮，0 次超卖。
- 取消和收款同时发生时，应退和实收对不上，已取消的也可能变回已付款 → 修法：记收款只在报名还是读到时的状态和金额才写入；取消只在收款笔数没变时才写入。先到的成功，后到的被拒并看到是谁。真 D1：70 轮 0 次对不上。
- 收款码按活动分开：还没做（Year End 前）。

### 活动邮箱（2026-11-24 Shiao 定；第一步，11/24 已上线，第十一次部署）

- 设置页「活动邮箱」卡片：**只有管理员能改，总管只能看**，经理、前台后台不给。三栏：管理员（固定：Cloudflare `REG_NOTIFY`，没设＝selecttango@gmail.com）、总管邮箱、副本邮箱（可不填）。
- 每封报名相关的信（收到、确认、候补、婉拒、催款、付款确认、取消、修改）和新报名通知，都**各自单独**寄一份给总管邮箱、副本邮箱、管理员；不用 Cc／Bcc，报名者看不到这些地址。副本标题前加「[副本]」，第一行写明是寄给哪位报名者（哪个编号）那封信的副本；**副本不附入场码**。同一个地址只寄一份；报名者本人就是其中一个地址时，不再寄副本给自己。给报名者的信没寄出就不寄副本；选「不寄信」的操作也不寄。
- 管理员那栏有开关「管理员也收信」（预设开）。关掉只在总管邮箱**已填而且已验证**时生效；没填或还没验证，管理员照收。
- 填总管邮箱：寄任命信给总管，**只附管理页的专属登入链接，不附密码**（Shiao 用微信或电话告诉总管）。还没任命总管时先存着，任命时才寄。总管已经在：后台只存链接的杂凑，拿不回原链接，所以产生新链接寄出，旧链接失效；密码和已登入的手机不变；信寄不出就把旧链接放回去。重设总管、经理升总管、按「重寄任命信」也都寄新链接。
- 验证：任命信里的链接多带一个码（`?m=`），总管打开就算验证了这个邮箱（登入页显示「邮箱已确认」，码随即从网址拿掉）。管理页上显示给管理员的链接没有这个码，用它登入不算。任命信现在两种阶段都直接寄到总管本人的邮箱（方案 1225），所以**总管在自己邮箱打开链接的验证，上线后照样算数**。只有 1225 以前寄到测试信箱、由别人代点的验证，上线后不算，要按「重寄任命信」请总管打开新信。总管在自己已登入的手机打开新链接，直接进管理页，不用先退出。
- 副本邮箱：填了就寄一封简短通知（不附链接）；任命总管（新任命、改总管邮箱、经理升总管）时也收一封简短通知，不附链接。重设、重寄不通知。
- 总管被删除或降为经理：总管邮箱自动清空，不再收副本，管理员照收。
- 测试阶段（没设 `REG_LIVE`；方案 1225，11/24 Shiao 定）：管理员、总管邮箱、副本邮箱**直接收**自己的信（副本、新报名通知、任命信、副本邮箱通知、转寄来的回信），标题前加「[测试]」。给报名者的信：收件人在测试名单上的直接寄本人，标题前加「[测试]」；其他人的只寄 selecttango@gmail.com，标题写「[TEST → 原收件人]」，所以名单外的人收不到任何测试信。
- 测试名单（方案 1225）：「活动邮箱」卡片最下面，管理员改、总管只能看，最多 10 个邮箱，只在测试阶段起作用（上线后卡片不再显示）。名单上的人可以用自己的邮箱报名、收信、真的回信测试。存在 `reg_setting` 的 `test_list`。实测步骤见 Google 文件《1225》。
- 第三步「活动专属邮箱」和转寄回信：见下一节。
- 程序：迁移 0026（`reg_setting`），`register.js` 的「活动邮箱」一节，`POST /social/admin/reg/mailto`，登入页 `/reg/login/hello` 收 `m`。测试 `social-worker/test/reg-mailto.test.mjs`。
- 一起修的旧问题（11/24 测出，main 上从 11/22 就有）：经理、总管的手机开过管理页后，管理页把这支手机的登入钥匙存进管理员的位置；之后在这支手机打开任何专属链接（包括自己被重设、改职务后拿到的链接）都显示「这台已经登入管理员」，签到页也不会跳出 12 小时再输密码。修法：管理页不再这样存；`tp.js` 不把手机钥匙当管理员，并清掉旧手机上留下的（`tp.js?v=3`）。

### 活动专属邮箱（第三步，2026-11-24 Shiao 定；11/24 已上线，第十二次部署；已绑定 bstw2027@tangoweekend.org）

- 每场活动一个专门收报名回信的地址，例如 `bstw2027@tangoweekend.org`。**管理员在「活动邮箱」卡片设定**（只填 @ 前面，3–32 个小写英文字母、数字或 -；info、huodong、subscribe、admin 等保留），总管只能看。
- **TP 自己去 Cloudflare 绑定**：按「绑定」后，后台用 Cloudflare 钥匙 `CF_MAIL_TOKEN` 加一条邮件路由规则「这个地址 → TP 后台（Worker tango-subscribe）」，记下规则编号；改地址或清空时，只删自己建的那条（而且只在它还是「这个地址 → TP 后台」时才删）。Cloudflare 上已有别的规则的地址、别的活动用了的地址，都不让用。
- 绑定后系统寄一封测试信到这个地址，**收到了才算「已绑定」**；从这时起这场活动报名信（和副本）的「回复」才改成这个地址，没绑定前照旧 info@。探戈通自己的信（任命信、通知）照旧 info@。
- 寄到活动专属邮箱的信：
  - **报名者寄来的**（寄件邮箱是这场活动某笔报名的邮箱或同行者邮箱）→ 单独转给总管邮箱、副本邮箱、管理员（照「管理员也收信」和验证的规则），附件（截图、PDF）照转；标题前加「[回信 编号 #记号]」，第一行写是谁、哪个编号、什么状态。
  - **总管、副本邮箱、管理员直接按「回复」**（回系统转来的信或报名信的副本）→ 以「Beijing Select Tango Weekend」的名义寄给那位报名者，「回复」还是活动专属邮箱，**报名者看不到你们的邮箱**；同时寄副本给其他人（Shiao 选的）。只有标题里带着系统给的「#记号」才会寄出：记号是报名编号的 HMAC，只出现在寄给你们的信里，所以别人冒用你们的邮箱也寄不出去。自己另写一封、或把记号删掉，系统回一封「没寄出」说明。
  - **不是报名者寄来的**（例如还没报名的人来问）→ 只转给管理员，「回复」直接对着寄件人（Shiao 选的）。
  - 没通过邮件验证（冒名）、自动回复、系统自己转出去的信 → 丢掉。超过 25MB 的信只通知管理员。
- 测试阶段（方案 1225）：转给总管、副本邮箱、管理员的信直接寄他们，标题前加「[测试]」；以活动名义寄给报名者的信照报名信的规矩（测试名单上的直接寄本人，其他人的只寄 selecttango）。从测试信箱回复「[TEST → 报名者]」的报名信，仍算那位报名者的回信。「[测试]」记号不会被带进下一封信的标题。
- 程序：`register.js` 的「活动专属邮箱」一节（`setEventMail`、`regInbound`），`live.js` 的 `email()`（huodong@ 以外的地址先问 TP），`social.js` 的 `deliver()` 可带附件。设定存在 `reg_setting`（`event_mail`、`event_mail_rule`、`event_mail_token`、`event_mail_ok`），不用新迁移。测试 `social-worker/test/reg-eventmail.test.mjs`。

### 调整金额：加收、减收（2026-11-26 Shiao 定「还没开始正式报名，先加进来」；规格书 v0.8；11/26 已上线，第十五次部署）

- **只有总管和管理员**能对一笔报名「加收」或「减收」，总管要再输一次密码（和退款一样）。经理看得到调整后的金额和纪录，不能调。
- **只改钱**，不改报名的场次、人数、房间（那是「修改报名」）；价格表照样锁定，不影响别人，不改名额；**不收 ¥50 手续费**。
- 管理页报名详情按「加收」或「减收」，填：金额（整数元）、算报名费还是住宿费（有住宿才问；算住宿费的，取消时照住宿退费期限处理）、**给报名者看的说明**（必填，写进信里和报名页）、内部备注（可不填，只有组织者看得到）。送出前画面先算给你看：原合计 → 新合计、已收多少、之后会怎样。哪一部分（报名费或住宿费）都不能减到 0 以下。
- 调整后：
  - 待审核、候补：金额先改好，确认后的付款信用新金额；减到 ¥0 的，一确认就是「已付款」并寄入场码。
  - 待付款、到场付款：应付金额马上改，付款期限不变；已收的钱够了就变「已付款」（第一次付清会寄入场码）。
  - **已付款又加收**：变成「到场付款」，入场码照样能用；报名页、管理页、门口扫码都显示还差多少，门口收齐才入场（想先付的回信联系）。收齐后又是「已付款」。
  - **已付款又减收**：多付的要退。管理页显示「退还多付 ¥X」和「记退款」，总管退了以后记一笔（要再输密码），不用取消报名。
  - 已取消、已婉拒：不能调。
- 之后取消报名，退款照调整后的金额算（已付的减 ¥50，过了住宿退费期限再减住宿费）。
- 每次都寄「金额调整」信给报名者（五种语言，照报名时选的）：加收或减收多少、说明、原合计和新合计、已付多少；还差钱的附付款说明（待付款的附收款码），多付的写明会退还。组织者照样收副本。**内部备注从来不寄给报名者**，报名页也不给。
- 纪录：每次一行处理纪录（谁、什么时候、加或减、多少、算哪部分、说明、内部备注），不能删；弄错了就反方向再调一次。名单导出最后多两栏 `adjust`（加减合计）、`adjust_why`。
- 一起补上：「修改报名」（后台才有，管理页没有画面）把已付款那笔改高时，也变「到场付款」，不会再显示成已付清。报名者在待审核时自己改表单、或「修改报名」重算金额时，之前的调整都保留。
- 程序：`register.js` 的 `regAct` 动作 `adjust`（权限沿用 `modify`，`/act` 要 `stepUp`）、`refund` 多了「已付款且多付」的情况、`adjOf`/`withAdj`（调整存在 `reg_log` 的 `adjust` 行，`reg.amount`、`reg.hotel_amount` 已含调整，**不用新迁移**）、信 `adj`。管理页 `adjForm`/`adjAfter`/`adjSubmit`，报名页 `adjText`。测试 `social-worker/test/reg-adjust.test.mjs`；浏览器测试 `~/atm-claude/tp-ui-tests/t200/adjust-ui.mjs`（不进仓库）。
- 平台那边（规格书 v0.8 第二批）以后用新表 `reg_adjust` 也行；北京这版先存在处理纪录里，搬家时一起带过去。
- 部署顺序（先问 Shiao）：记书签 → 部署 worker（不用迁移、不改 Cloudflare 设定）→ 合并网页（管理页、报名页）。网页不能比后台先上：旧后台不认得 `adjust`，按「加收」只会说没成功。回退：worker 退回上一版就好；已经调过的金额留在 `reg.amount` 里照样对，只是旧程序不再显示调整的明细，报名者改待审核的表单时会按表单重算（调整掉了）。之后 #450（12/1 上线）和平台那 5 个 PR 要接到新的 main 上。
